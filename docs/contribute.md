# Contributing

Documentation should move with the project. If you change hardware, wiring, software, or experimental assumptions, update the relevant page in the same pull request.

## Writing style

- Prefer concrete steps over vague descriptions.
- Link to files instead of saying "in the code".
- Add photos, diagrams, or screenshots when they reduce ambiguity.
- Record failed approaches when they would save future time.
- Put TODOs where knowledge is missing, but make them specific.

## Local docs workflow

```bash
nvm use
npm install
npm run start
```

The local site runs at `http://localhost:3000/Quadruped/`.
